# 给守望先锋英雄起名字

一个完全离线、使用原生 HTML、CSS 和 JavaScript 制作的第一印象记录网页。玩法已经从旧版的“四选一猜英雄”改为：查看英雄图片，从本局全部可用名称中为每位英雄分配一个名字，并写下选择理由；完成全部分配并确认提交后，页面才会揭晓真实名称和猜对结果。

这个项目关注的不只是正确率，更希望记录一个没玩过《守望先锋》的人如何根据人物形象理解这些英雄名称。

## 直接运行

项目已经包含本地英雄图标和全身照，**不需要重新下载图片，也不需要运行资源下载脚本**。

直接双击 `index.html` 即可开始。页面支持 `file://` 协议，不需要本地服务器、Node.js、npm、Vite 或网络连接。

脚本加载顺序为：

1. `heroes.js`：现有英雄数据和本地图片路径；
2. `core.js`：不依赖 DOM 的分配、存档、统计和导入导出逻辑；
3. `script.js`：页面渲染与交互。

## 游戏玩法

开始页面提供三组设置：

- 图片模式：英雄图标、英雄全身照；
- 英雄范围：全部英雄、重装、输出、支援；
- 游戏方式：逐个填写、全部列表。

职责范围同时决定图片范围和名称池。例如选择“重装”时，本局只展示重装英雄，名称池也只包含重装英雄名称。

每局开始时会用 Fisher–Yates 算法分别打乱英雄顺序和名称顺序。每位英雄只出现一次，每个名称默认只能使用一次。修改分配时，旧名称会自动释放回名称池。

### 逐个填写

默认模式。每次显示一位英雄，可以搜索当前仍可用的中文名或英文名、从名称按钮网格中选择名称，并填写 1–200 字的理由。名称和有效理由都填写完成且图片加载成功后，才能确认并进入下一位。

可以返回上一位、暂存草稿，或打开“当前分配表”跳转修改。最终提交前不会显示当前图片对应的真实名称，也不会判断猜测是否正确。

### 全部列表

一次显示本局全部英雄编辑卡片，适合统一比较和检查。每张卡片包含图片、名称下拉框、理由输入框和完成状态。已保存卡片会锁定，点击“编辑”后可以重新分配。图片使用延迟加载，手机端为单列布局。

## 图片故障

页面会先尝试 `heroes.js` 中的主图片，再依次尝试现有备用图片，全程不会联网请求 Wiki 或下载资源。

如果所有本地路径都加载失败，页面显示不包含真实名称的通用占位区域。玩家可以明确跳过该英雄；跳过不会占用名称，不算猜错，也不进入正确率分母，结果页会标记“因图片故障跳过”。

## 保存与继续

页面用带版本号和英雄数据签名的 `localStorage` 存储：

- 上次选择的图片模式、英雄范围和游戏方式；
- 当前未完成游戏、英雄顺序和名称顺序；
- 每位英雄的名称 ID、理由、完成/跳过状态；
- 当前英雄位置和已占用名称；
- 最近一次完整结果。

所有本地存储读写都有异常保护。刷新页面后，开始页会提示继续未完成游戏或确认放弃。如果 `heroes.js` 的英雄数据发生变化，旧存档会被判定为不兼容，并提示清除，不会直接让页面崩溃。

## 结果、分享与导入导出

全部完成后，页面会再次确认是否提交。确认后本局锁定，并显示：

- 英雄图片；
- 玩家猜测的中英文名；
- 真实中英文名和职责；
- “✓ 猜对”“✕ 猜错”或“因图片故障跳过”；
- 玩家填写的完整理由。

结果可以筛选“全部 / 只看猜对 / 只看猜错”，也可以按本局顺序、猜错优先、真实职责或真实中文名排序。

结果页还支持：

- 再玩一次、返回设置、切换图片模式再玩；
- 复制纯文字结果；
- 打印或保存为 PDF；
- 进入适合纵向截图的分享长图模式；
- 导出带版本号的 JSON；
- 导入并严格校验本项目导出的 JSON。

导入会检查版本、必需字段、英雄 ID、名称 ID、职责范围、重复分配、统计值和当前 `heroes.js` 的兼容性。无效文件只会显示清晰错误，不会替换当前结果。

## 键盘与无障碍

- 所有名称选项都是真实 `button`，所有控件支持 Tab 导航；
- Enter 可确认逐个填写模式的当前有效分配；
- `/` 可在非输入状态下聚焦名称搜索框；Ctrl+F 保留浏览器默认行为；
- Escape 可关闭对话框；对话框使用模态语义并恢复原焦点；
- `aria-live` 播报名选择、保存、错误和页面推进；
- 选中、完成、猜对和猜错都同时使用文字或符号，不只依赖颜色；
- 支持 `focus-visible`、响应式布局和 `prefers-reduced-motion`。

```text
overwatch-hero-quiz/
├─ index.html                 # 语义化页面与对话框结构
├─ style.css                  # 游戏、结果、分享和打印样式
├─ script.js                  # DOM 状态、渲染、事件与本地保存
├─ core.js                    # 纯逻辑模块
├─ heroes.js                  # 现有 52 名英雄数据（保持原格式）
├─ asset_report.json          # 现有本地资源报告
├─ assets/
│  ├─ icons/                  # 现有英雄图标及备用图
│  └─ fullbody/               # 现有英雄全身照及备用图
├─ tools/
│  └─ download_assets.py      # 历史资源整理工具；正常运行无需执行
└─ tests/
   └─ run_tests.py            # 静态、资源和 core.js 自动测试
```

## 英雄数据

`heroes.js` 中每名英雄继续使用现有字段：

- `id`：中性、稳定且唯一的英雄 ID；
- `nameZh` / `nameEn`：简体中文名和英文名；
- `role`：`tank`、`damage` 或 `support`；
- `icon` / `iconFallbacks`：本地图标主路径和备用路径；
- `fullbody` / `fullbodyFallbacks`：本地全身照主路径和备用路径；
- `sources`：资料与图片来源；
- `download`：已有资源整理元数据。

游戏中的图片与名称分配始终通过 ID 建立关系，不依赖数组下标或显示文本。

## 测试

如需执行项目自带的自动检查：

```bash
python tests/run_tests.py
```

测试会校验英雄数据、全部现有图片路径和哈希、HTML/CSS/JavaScript 禁止项，并通过 Node.js 实际运行 `core.js`，覆盖 Fisher–Yates、职责筛选、名称唯一占用、更换名称后的释放、存档恢复、统计、跳过、结果导出和无效导入。测试不下载图片，也不会修改 `heroes.js` 或 `assets/`。
